# Интеграция в Nafanya

Менеджер реализует выбор приложений для прямого подключения поверх установленного sing-box. Пользователь выбирает игровой процесс или файл, включает обход и применяет список.

## Текущая реализация

1. Из активного `tun.json` читается локальный набор `geoip-ru`. Проверяется, что он подключён к выходу типа `direct` и используется только для IP-маршрутизации.
2. В наборе обновляется условие `process_path_regex` с точными путями выбранных игр.
3. Условия предыдущего применения узнаются по сохранённому списку шаблонов. Остальные правила сохраняются.
4. Установленный sing-box компилирует набор. Результат декомпилируется и сравнивается с ожидаемым содержимым.
5. Перед записью создаются резервные копии правил и настроек менеджера. Файл обновляется с блокировкой и проверкой хеша.
6. sing-box автоматически подхватывает локальный набор. Уже открытые соединения сохраняют свой прежний выход до переподключения.

При первом запуске распознаётся ранее добавленное одиночное правило League of Legends для стандартного каталога на диске D. Оно становится управляемым через общий список игр. Для Fortnite предусмотрено семейство собственных исполняемых файлов в каталоге игры.

## Предлагаемая интеграция

В приложении стоит создать отдельный локальный набор `games-direct`, направленный в Direct до общих правил маршрутизации. Выбранные пути сохранять в настройках Nafanya, а набор генерировать при изменении выбора и старте клиента.

Это позволит отделить игровые исключения от обновляемой базы GeoIP и убрать зависимость от категории «Российские сайты».

Экран Flutter может использовать ту же модель выбора. Обнаружение процессов получает путь исполняемого файла и объединяет несколько PID одного файла в одну строку. Для защищённых процессов ошибки чтения пути обрабатываются отдельно.

Локальный API позволяет показать пользователю реальный выход активного игрового соединения. Токен доступа следует держать в памяти и использовать только для обращения к локальному контроллеру.

## Файлы

- `src/RuleManager.cs` — чтение конфигурации, сборка и проверка правил, резервные копии, откат и запрос соединений.
- `src/Models.cs` — список игр и метаданные последнего применения.
- `src/MainWindow.cs` и `src/MainWindow.xaml` — выбор игр и сохранение.
- `src/ProcessPicker.cs` и `src/ProcessPicker.xaml` — поиск запущенных приложений.
- `src/GlassUi.cs` и `src/GlassTheme.xaml` — общие окна и оформление.

## Проверенные сценарии

- Снятие Fortnite с сохранением правила League и возврат исходных байтов через откат.
- Снятие обеих игр и восстановление правил вместе с сохранённым выбором.
- Применение и откат при сохранении процесса VPN.
- Выбор существующего исполняемого файла из работающего процесса.
- Привязки переключателей, счётчик выбора, удаление карточки и фильтрация процессов.
- Отрисовка главного окна при 1060×740 и 900×640.

Для интеграционного выпуска следует проверить TCP и UDP в реальных матчах, смену каталога игры, голосовой чат, переподключение клиента, обновление GeoIP и работу одновременно с другим VPN.

## Документация sing-box

Локальные наборы поддерживают автоматическую перезагрузку при изменении файла. Правила по пути процесса поддерживаются на Windows. [Локальные наборы](https://sing-box.sagernet.org/configuration/rule-set/), [условия правил](https://sing-box.sagernet.org/configuration/rule-set/headless-rule/).
